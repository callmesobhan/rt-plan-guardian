# Rule catalog

> Generated by `rtpg rules --format md` - do not edit by hand (a test fails if this file is out of date).

51 built-in rules. Severity shown is the default; rulesets may override it. `requires` lists the DICOM-RT objects that must be supplied, otherwise the rule is reported as SKIPPED.

## Input completeness

### INPUT-001 - Required DICOM-RT objects were supplied

A missing object means downstream cross-checks cannot run. The ruleset states which objects it expects, so an absent file is a visible failure rather than a silent gap.

- **Default severity:** error
- **Requires:** nothing
- **Applies to:** every plan
- **Reference:** SOP Class UIDs: RT Plan, RT Structure Set, RT Dose
- **Parameters (defaults):**
  - `required`: `["rtplan", "rtstruct", "rtdose"]`

### INPUT-002 - Every supplied RT object belongs to the reviewed case

When a folder holds several plans, doses and structure sets, objects are assembled into cases by the UID references the files carry. An object that cannot be linked (a dose for a plan that was not supplied, a structure set no plan uses) is reported here instead of being silently dropped or guessed into the wrong case.

- **Default severity:** warning
- **Requires:** nothing
- **Applies to:** every plan
- **Reference:** RT Dose - ReferencedRTPlanSequence; RT Plan - ReferencedStructureSetSequence

### INPUT-003 - Exactly one plan-level dose identifies the case dose

Several dose files may belong to one plan (per-beam, per-fraction, plan sum). Dose rules evaluate the one whose DoseSummationType is PLAN; if there is none or more than one the choice is ambiguous and the reviewer must say which is meant.

- **Default severity:** warning
- **Requires:** RTDOSE
- **Applies to:** every plan
- **Reference:** RT Dose Module - DoseSummationType (3004,000A)

## Patient identity

### IDENT-001 - Patient ID is identical across all objects

Objects from different patients must never be reviewed or delivered together. This is the highest-consequence consistency check in the tool.

- **Default severity:** error
- **Requires:** nothing
- **Applies to:** every plan
- **Reference:** DICOM Patient Module - PatientID (0010,0020)

### IDENT-002 - Patient name, birth date and sex agree across objects

A second, independent identity signal: catches the case where an ID was re-keyed but the demographics reveal different patients.

- **Default severity:** warning
- **Requires:** nothing
- **Applies to:** every plan
- **Reference:** DICOM Patient Module - PatientName, PatientBirthDate, PatientSex

### IDENT-003 - Each object has its own non-empty SOP Instance UID

Duplicate UIDs mean the same object was supplied twice under different roles, or a copy/paste export error - and make UID-based linkage checks meaningless.

- **Default severity:** error
- **Requires:** nothing
- **Applies to:** every plan
- **Reference:** DICOM SOP Common Module - SOPInstanceUID (0008,0018)

## Cross-object linkage

### LINK-001 - RT Plan references the supplied RT Structure Set

Beam isocentres and dose-reference ROIs are only meaningful against the structure set the plan was made on. A different structure set silently changes what 'target' means.

- **Default severity:** error
- **Requires:** RTPLAN, RTSTRUCT
- **Applies to:** every plan
- **Reference:** RT General Plan Module - ReferencedStructureSetSequence (300C,0060)

### LINK-002 - RT Dose references the supplied RT Plan

A dose grid computed for a different plan (or an earlier revision) is the classic stale-export failure: numbers look plausible but describe the wrong beams.

- **Default severity:** error
- **Requires:** RTPLAN, RTDOSE
- **Applies to:** every plan
- **Reference:** RT Dose Module - ReferencedRTPlanSequence (300C,0002)

### LINK-003 - RT Dose and RT Structure Set share a Frame of Reference

Contours and dose are only spatially comparable if they use the same coordinate system. A mismatch means dose-to-structure statistics would be computed in the wrong place.

- **Default severity:** error
- **Requires:** RTSTRUCT, RTDOSE
- **Applies to:** every plan
- **Reference:** Frame of Reference Module - FrameOfReferenceUID (0020,0052)

### LINK-004 - ROIs referenced by the plan's dose references exist in the structure set

Prescriptions and constraints point at ROIs by number. A dangling number means the prescription is attached to nothing (or to the wrong structure after a renumber).

- **Default severity:** error
- **Requires:** RTPLAN, RTSTRUCT
- **Applies to:** every plan
- **Reference:** RT Prescription Module - DoseReferenceSequence / ReferencedROINumber (3006,0084)

## Structure set

### STRUCT-001 - ROI numbers, names and references are well-formed

Everything downstream addresses ROIs by number. Duplicate numbers, unnamed ROIs or orphaned contour data make 'which structure is this?' ambiguous.

- **Default severity:** error
- **Requires:** RTSTRUCT
- **Applies to:** every plan
- **Reference:** Structure Set Module - StructureSetROISequence; ROI Contour Module

### STRUCT-002 - Required ROIs are present

Site policy usually demands certain structures (a target, an external contour, key OARs). Each entry in `required_roi_patterns` is a case-insensitive regex searched in the ROI names.

- **Default severity:** error
- **Requires:** RTSTRUCT
- **Applies to:** every plan
- **Reference:** Local policy; naming guidance: AAPM TG-263
- **Parameters (defaults):**
  - `required_roi_patterns`: `[]`

### STRUCT-003 - Every ROI contains contour data

An ROI with a name but no contours is invisible to any dose statistic that uses it - a quiet way for an OAR constraint to be 'met'. ROIs matching `ignore_patterns` are exempt.

- **Default severity:** warning
- **Requires:** RTSTRUCT
- **Applies to:** every plan
- **Reference:** ROI Contour Module - ContourSequence (3006,0040)
- **Parameters (defaults):**
  - `ignore_patterns`: `[]`

### STRUCT-004 - Contours are well-formed for their geometric type

Declared point counts must match the data, closed polygons need at least three points, and all points of a planar contour must share one z. Open non-planar contours (brachytherapy catheters and applicators) and single POINTs are valid DICOM and are checked against their own type. Malformed contours corrupt volume and dose statistics without any visible error in most viewers.

- **Default severity:** error
- **Requires:** RTSTRUCT
- **Applies to:** every plan
- **Reference:** ROI Contour Module - ContourGeometricType, NumberOfContourPoints, ContourData
- **Parameters (defaults):**
  - `planar_tolerance_mm`: `0.01`
  - `min_points`: `3`
  - `allowed_geometric_types`: `["CLOSED_PLANAR", "OPEN_PLANAR", "OPEN_NONPLANAR", "POINT"]`

### STRUCT-005 - Every ROI has an interpreted type

RTROIInterpretedType (PTV, ORGAN, EXTERNAL...) lets downstream systems treat targets and organs differently. Missing types push that guesswork onto name matching.

- **Default severity:** warning
- **Requires:** RTSTRUCT
- **Applies to:** every plan
- **Reference:** RT ROI Observations Module - RTROIInterpretedType (3006,00A4)

### STRUCT-006 - ROI names follow the configured nomenclature (e.g. AAPM TG-263)

Standard structure names make plans comparable and let downstream tools recognise organs. Names must be in the supplied nomenclature list (one name per line; for AAPM TG-263 convert the official worksheet with scripts/tg263_xls_to_txt.py), fit `max_name_length` (TG-263: 16 characters) and may alternatively match one of `additional_allowed_patterns` (e.g. dose-suffixed target names). The list file is read from `nomenclature_file` or the RTPG_NOMENCLATURE_FILE environment variable; with neither the rule is not applicable. The list is never bundled: AAPM states no reuse licence.

- **Default severity:** warning
- **Requires:** RTSTRUCT
- **Applies to:** every plan
- **Reference:** AAPM TG-263 (Mayo et al., IJROBP 2018) nomenclature worksheet
- **Parameters (defaults):**
  - `nomenclature_file`: `""`
  - `max_name_length`: `16`
  - `case_sensitive`: `true`
  - `additional_allowed_patterns`: `[]`
  - `ignore_patterns`: `[]`

## Plan & prescription

### PLAN-001 - Plan approval status is acceptable

Only plans in an approved state should be exported to delivery or QA systems. `allowed_statuses` lists the ApprovalStatus values your site accepts. AAPM MPPG 11.a (Table 8) lists physician and physicist plan approval among the initial-check items.

- **Default severity:** warning
- **Requires:** RTPLAN
- **Applies to:** every plan
- **Reference:** Approval Module - ApprovalStatus (300E,0002); AAPM MPPG 11.a Tables 7-8
- **Parameters (defaults):**
  - `allowed_statuses`: `["APPROVED"]`

### PLAN-002 - Plan has deliverable content of a supported technique

A plan with neither treatment beams nor brachytherapy application setups cannot be delivered, and would otherwise pass every technique-specific rule as 'not applicable'. Beams of an unexpected radiation type (neutron...) are flagged because the other checks do not cover them. `allowed_radiation_types` lists the types your site delivers.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** every plan
- **Reference:** RT Beams / RT Ion Beams Modules - RadiationType; RT Brachy Application Setups Module
- **Parameters (defaults):**
  - `allowed_radiation_types`: `["PHOTON", "ELECTRON", "PROTON", "ION", "MIXED_ION"]`

### PLAN-003 - Number of fractions is within the configured range

Catches zero/negative fractions and typos such as 300 instead of 30.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** every plan
- **Reference:** RT Fraction Scheme Module - NumberOfFractionsPlanned (300A,0078)
- **Parameters (defaults):**
  - `min_fractions`: `1`
  - `max_fractions`: `60`

### PLAN-004 - Prescription equals summed per-fraction dose x fractions

Two independent statements of the same quantity must agree: the prescribed target dose, and the per-fraction dose of the plan's beams (BeamDose) and/or brachytherapy application setups (BrachyApplicationSetupDose) multiplied by the number of fractions. A mismatch is a typo or a stale edit in one of them (AAPM MPPG 11.a: prescription and fractional/total dose agree with the plan). Only single-fraction-group, single-prescription plans are evaluated; others are reported as SKIPPED. Radiosurgery plans prescribe to an isodose line (Gamma Knife: BeamDose is the dose at the maximum-dose point), so the sum is scaled by the prescription isodose % - from the ruleset, or from the Elekta GammaPlan private element (an empirical reading, see plan_model.py) - and the identity is still verified.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** every plan
- **Reference:** RT Prescription Module - TargetPrescriptionDose; RT Fraction Scheme - BeamDose, BrachyApplicationSetupDose; AAPM MPPG 11.a Tables 7-8
- **Parameters (defaults):**
  - `tolerance_percent`: `1.0`
  - `prescription_isodose_percent`: `0.0`
  - `use_vendor_isodose`: `true`

### PLAN-005 - Treatment machine is named, consistent and allowed

All beams of a plan should be delivered on one machine, and it should be one the site has commissioned the plan type for (AAPM MPPG 11.a: treatment scheduled on the correct machine). For brachytherapy the afterloader named in TreatmentMachineSequence is checked. Set `allowed_machines` to enforce a whitelist.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** every plan
- **Reference:** RT Beams Module - TreatmentMachineName (300A,00B2); Brachy - TreatmentMachineSequence
- **Parameters (defaults):**
  - `allowed_machines`: `[]`
  - `require_single_machine`: `true`

## Beams & delivery (photon, electron, ion)

### BEAM-001 - Beam numbers are unique and match the fraction groups

Dose and MU are attached to beams by number via the fraction groups. A duplicated beam number, a referenced beam that does not exist, or a treatment beam that no fraction group delivers means the plan as exported is not the plan as intended.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** electron, ion, neutron, photon, proton
- **Reference:** RT Beams / RT Ion Beams Module - BeamNumber; RT Fraction Scheme - ReferencedBeamSequence

### BEAM-002 - Control points are complete and meterset weights are monotonic

Control points define how the beam is delivered. They must be numbered 0..N-1, the count must match the declaration, and cumulative meterset weight must run from 0 to FinalCumulativeMetersetWeight without decreasing; otherwise MU would be delivered at the wrong gantry/MLC/energy state.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** electron, ion, neutron, photon, proton
- **Reference:** RT Beams / RT Ion Beams Module - Control Point Sequence, CumulativeMetersetWeight (300A,0134)
- **Parameters (defaults):**
  - `weight_tolerance`: `0.0001`

### BEAM-003 - Gantry, collimator and couch angles are present and in [0, 360)

Angles outside the DICOM range, or absent on the first control point, mean the geometry is undefined or was edited by hand. Required angles depend on the technique: ion beams have no collimator angle, so only gantry is required there.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** electron, ion, neutron, photon, proton
- **Reference:** RT Beams Module - GantryAngle, BeamLimitingDeviceAngle, PatientSupportAngle

### BEAM-004 - Nominal beam energy is present, positive and allowed

A zero or missing energy cannot be delivered. `allowed_energies` maps a radiation type (PHOTON, ELECTRON, PROTON, ION) to the energies commissioned on your machines (MV for photons, MeV for electrons, MeV/u for ions) to catch an energy that does not exist.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** electron, ion, neutron, photon, proton
- **Reference:** RT Beams Module - NominalBeamEnergy (300A,0114)
- **Parameters (defaults):**
  - `allowed_energies`: `{}`

### BEAM-005 - Beam meterset is present, positive and within limits for its unit

Meterset per beam must exist and be plausible. Limits are set per dosimeter unit because the unit is not always MU: cobalt and Gamma Knife plans use MINUTE, particle systems may use NP. Zero/negative values and values beyond the configured limit indicate a calculation or export error.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** electron, ion, neutron, photon, proton
- **Reference:** RT Fraction Scheme Module - BeamMeterset (300A,0086); RT Beams - PrimaryDosimeterUnit (300A,00B3)
- **Parameters (defaults):**
  - `limits`: `{"MU": [1.0, 2000.0], "MINUTE": [0.0, 120.0], "NP": [0.0, 1000000000000000.0]}`

### BEAM-006 - Beam isocentre lies inside a target volume

Cross-checks plan geometry against the structure set: the isocentre should normally be inside the target. Legitimate exceptions exist (multi-target SBRT, fixed-point isocentres, electron SSD set-ups), hence WARNING severity. Targets come from the plan's DoseReferenceSequence (matched to ROIs by number, or by description for SITE references); `target_patterns` (regex on ROI names) is the fallback. Electron beams are skipped by default via `radiation_types`. Multi-isocentre plans (e.g. Gamma Knife shots) check each one.

- **Default severity:** warning
- **Requires:** RTPLAN, RTSTRUCT
- **Applies to:** electron, ion, neutron, photon, proton
- **Reference:** RT Beams Module - IsocenterPosition (300A,012C); Structure Set contours
- **Parameters (defaults):**
  - `target_patterns`: `["^PTV"]`
  - `radiation_types`: `["PHOTON", "PROTON", "ION", "MIXED_ION"]`

### BEAM-007 - MLC leaves and jaws are physically sane (no crossed pairs, within travel)

Checks every control point: opposing leaves/jaws do not cross (bank A <= bank B, with at most `min_leaf_gap_mm` closure) and positions stay within a configured travel limit. Crossed leaves are a physically impossible delivery. The check pairs the first half of `LeafJawPositions` with the second half, independent of how the export declares the device (see BEAM-008 for declaration conformance).

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** photon
- **Reference:** RT Beams Module - BeamLimitingDevicePositionSequence, LeafJawPositions (300A,011C)
- **Parameters (defaults):**
  - `min_leaf_gap_mm`: `0.0`
  - `max_abs_position_mm`: `200.0`

### BEAM-008 - Beam-limiting devices are declared consistently with their positions

DICOM requires every positioned device to be declared in BeamLimitingDeviceSequence and its position count to equal 2 x NumberOfLeafJawPairs. Some vendors export jaws/collimators with a pair count of 0; that is a conformance deviation (a warning) rather than a physical hazard, so it is reported separately from BEAM-007.

- **Default severity:** warning
- **Requires:** RTPLAN
- **Applies to:** photon
- **Reference:** RT Beams Module - BeamLimitingDeviceSequence, NumberOfLeafJawPairs (300A,00BC)

## Proton / ion beams

### ION-001 - Ion beam definition and scanning parameters are complete

A scanned ion beam is only deliverable if the scan mode is known, the control points come in pairs (two per irradiation segment), the machine geometry is given (virtual source-axis distances, dosimeter unit), and every modulated control point carries its spot-tune ID, spot count, spot map, weights and painting count. Ions heavier than protons must also identify the species.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** ion, proton
- **Reference:** DICOM PS3.3 C.8.8.25 RT Ion Beams Module (Scan Mode, Number of Control Points, ...)
- **Parameters (defaults):**
  - `allowed_scan_modes`: `["NONE", "UNIFORM", "MODULATED", "MODULATED_SPEC"]`

### ION-002 - Scan spot maps and weights are well-formed

For N spots the position map holds 2N values (x,y pairs in the isocentric plane), there are N weights, the declared count matches, weights are finite and non-negative, and the painting count is at least one. A truncated map or a negative weight corrupts the delivery silently.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** ion, proton
- **Reference:** DICOM PS3.3 C.8.8.25 - Scan Spot Position Map, Scan Spot Meterset Weights

### ION-003 - Spot weights and segment pairing follow the DICOM scanning model

Each irradiation segment is a pair of control points with identical spot positions. The first carries the weights, which must sum to the cumulative-meterset step to the next control point; the second carries zero weights; the cumulative meterset must not change between segments. A violation means the planned layer MU and the delivered layer MU differ.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** ion, proton
- **Reference:** DICOM PS3.3 C.8.8.25.7 Ion Control Point Sequence
- **Parameters (defaults):**
  - `relative_tolerance`: `0.001`

### ION-004 - Beam energies are positive and within the machine range

Every control point's nominal energy (MeV per nucleon at the nozzle) must be positive and inside the range the accelerator and energy-selection system can deliver. The shipped bounds are deliberately wide (they only catch zero/absurd values): set the real range of your facility.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** ion, proton
- **Reference:** DICOM PS3.3 C.8.8.25 - Nominal Beam Energy (300A,0114); facility commissioning data
- **Parameters (defaults):**
  - `min_energy_mev`: `0.0`
  - `max_energy_mev`: `1000.0`

### ION-005 - Scan spots lie within the maximum scan field

Spot positions are in mm in the isocentric plane. A spot beyond the nozzle's scanning range cannot be delivered. The shipped limit is a generic upper bound; set your nozzle's.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** ion, proton
- **Reference:** DICOM PS3.3 C.8.8.25 - Scan Spot Position Map (300A,0394); nozzle specification
- **Parameters (defaults):**
  - `max_abs_spot_position_mm`: `300.0`

### ION-006 - Range shifter and snout settings are consistent

Range-shifter settings must reference a range shifter the beam declares, and a beam with a snout must give its position (mm from isocentre) within a configured travel. Dangling references mean the physical accessory in the nozzle is unknown to the plan.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** ion, proton
- **Reference:** DICOM PS3.3 C.8.8.25 - Range Shifter Sequence, Range Shifter Settings, Snout Position (300A,030D)
- **Parameters (defaults):**
  - `max_snout_position_mm`: `700.0`

## Electron beams

### ELEC-001 - Electron beams specify an applicator of an allowed type

The applicator (cone) defines the electron field's collimation and the air gap; a plan without one, or with an undefined type, cannot be matched to the physical set-up. AAPM MPPG 11.a Table 9 lists applicator, cone and block code among the electron checks. `allowed_applicator_ids` can whitelist the cones your clinic owns.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** electron
- **Reference:** DICOM RT Beams Module - ApplicatorSequence (300A,0107); AAPM MPPG 11.a Table 9
- **Parameters (defaults):**
  - `allowed_applicator_types`: `["ELECTRON_SQUARE", "ELECTRON_RECT", "ELECTRON_CIRC", "ELECTRON_SHORT", "ELECTRON_OPEN", "INTRAOPERATIVE", "STEREOTACTIC"]`
  - `allowed_applicator_ids`: `[]`

### ELEC-002 - Electron cutouts (aperture blocks) are defined and well-formed

Electron fields are shaped by a cutout in the applicator insert. The plan must declare it (unless the applicator is an open type), the declared block count and point count must match the data, the outline needs at least three points, and coordinates must be finite and within a plausible extent. A missing or corrupt block means the dose was calculated for a field that cannot be reproduced.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** electron
- **Reference:** DICOM RT Beams Module - BlockSequence (300A,00F4), BlockData (300A,0100); AAPM MPPG 11.a Table 9
- **Parameters (defaults):**
  - `require_cutout`: `true`
  - `max_abs_block_coordinate_mm`: `300.0`

### ELEC-003 - Source-to-surface distance is given and plausible

Electron output depends strongly on SSD (virtual source, air gap). It must be present on the first control point and lie in the configured range; extended-SSD set-ups are legitimate but deserve a human look, hence WARNING severity.

- **Default severity:** warning
- **Requires:** RTPLAN
- **Applies to:** electron
- **Reference:** DICOM RT Beams Module - SourceToSurfaceDistance (300A,0130)
- **Parameters (defaults):**
  - `min_ssd_mm`: `800.0`
  - `max_ssd_mm`: `1200.0`

## Brachytherapy

### BRACHY-001 - Brachytherapy sources are fully and plausibly defined

Each source needs a unique number, an isotope name, a positive half-life that agrees with the isotope when it is a recognised one, and a positive strength (air kerma rate for gamma emitters, including exports that declare SourceStrengthUnits=AIR_KERMA_RATE; SourceStrength for DOSE_RATE_WATER beta sources). Dose is proportional to this strength, so an implausible value propagates directly into every dwell time.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** brachy
- **Reference:** DICOM PS3.3 C.8.8.15 Source Sequence; AAPM MPPG 11.a Table 7 (source strength); half-lives: BIPM DDEP evaluations
- **Parameters (defaults):**
  - `half_life_tolerance_percent`: `2.0`

### BRACHY-002 - Total Reference Air Kerma equals source strength x total channel time

Two independent quantities in the plan must agree: TotalReferenceAirKerma (uGy at 1 m) and the sum over channels of the source's air kerma rate (uGy/h at 1 m) times channel time / 3600. A mismatch means a dwell time or source strength was edited after the total was written. Verified on real Varian and Elekta exports (agreement to 5 significant figures).

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** brachy
- **Reference:** DICOM PS3.3 C.8.8.15 - Total Reference Air Kerma (300A,0250), Channel Total Time (300A,0286)
- **Parameters (defaults):**
  - `tolerance_percent`: `1.0`

### BRACHY-003 - Channels and dwell control points are structurally consistent

Per channel: unique number, existing source, positive length and total time, the right number of control points (2N for stepwise movement), indices 0..n-1, cumulative time weight starting at 0, never decreasing, ending at FinalCumulativeTimeWeight and flat between dwell pairs, the two control points of a pair at one position, and positions inside the channel. AAPM MPPG 11.a Table 7 lists channel assignment, index length and first dwell position.

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** brachy
- **Reference:** DICOM PS3.3 C.8.8.15 Channel Sequence, Brachy Control Point Sequence; AAPM MPPG 11.a Table 7
- **Parameters (defaults):**
  - `time_weight_tolerance`: `1e-06`
  - `position_tolerance_mm`: `0.01`

### BRACHY-004 - Source strength reference date is not in the future and not stale

The planned source strength is valid at the SourceStrengthReference date/time. That must not be after the plan date, and (warning) should not be many days before it unless the strength was decay-corrected: AAPM MPPG 11.a Table 7 asks the physicist to check the source strength against the decay table. The note reports the decay factor between reference and plan date for the source's half-life. `max_source_age_days` suits Ir-192 on a quarterly exchange; set it for your isotope and exchange cycle.

- **Default severity:** warning
- **Requires:** RTPLAN
- **Applies to:** brachy
- **Reference:** DICOM PS3.3 C.8.8.15 - Source Strength Reference Date/Time; AAPM MPPG 11.a Table 7
- **Parameters (defaults):**
  - `max_source_age_days`: `120.0`

### BRACHY-005 - Application setups agree with the fraction scheme

Setup numbers must be unique, the fraction group must declare the right number of setups and reference only setups that exist, and every setup must be delivered by some fraction group. Otherwise the prescription is attached to an applicator that is not in the plan (or the plan carries one that is never treated).

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** brachy
- **Reference:** DICOM PS3.3 - Referenced Brachy Application Setup Sequence (300C,000A), Application Setup Number (300A,0234)

### BRACHY-006 - Dwell times are non-negative and bounded; step sizes are allowed

Dwell times derived from the time weights must not be negative or exceed `max_dwell_s`, and a channel must have at least one dwell position. If `allowed_step_sizes_mm` is set, every spacing between consecutive dwell positions must be a whole multiple of one of those steps (AAPM MPPG 11.a Table 7 lists step size, number of dwell positions and first dwell position among the HDR checks).

- **Default severity:** error
- **Requires:** RTPLAN
- **Applies to:** brachy
- **Reference:** AAPM MPPG 11.a Table 7; DICOM PS3.3 C.8.8.15 Control Point Relative Position
- **Parameters (defaults):**
  - `max_dwell_s`: `600.0`
  - `allowed_step_sizes_mm`: `[]`
  - `step_tolerance_mm`: `0.01`

## Dose

### DOSE-001 - Dose units, type and summation are as expected

Absolute dose statistics are only meaningful for physical dose in Gy summed over the plan. Relative dose, per-fraction or per-beam grids must not be compared with the plan prescription. Proton/ion plans may legitimately carry EFFECTIVE (RBE-weighted) dose.

- **Default severity:** error
- **Requires:** RTDOSE
- **Applies to:** every plan
- **Reference:** RT Dose Module - DoseUnits, DoseType, DoseSummationType
- **Parameters (defaults):**
  - `allowed_units`: `["GY"]`
  - `allowed_dose_types`: `["PHYSICAL"]`
  - `allowed_dose_types_charged_particle`: `["PHYSICAL", "EFFECTIVE"]`
  - `allowed_summation_types`: `["PLAN"]`

### DOSE-002 - Dose grid is internally consistent

Pixel data size must match Rows x Columns x NumberOfFrames, the frame offset vector must match the frame count and be monotonic, scaling must be positive, and the dose must not be all zero. A corrupt grid can still 'load' and produce plausible-looking nonsense.

- **Default severity:** error
- **Requires:** RTDOSE
- **Applies to:** every plan
- **Reference:** RT Dose Module / Multi-frame Overlay - Rows, Columns, NumberOfFrames, GridFrameOffsetVector, DoseGridScaling

### DOSE-003 - Dose grid resolution is fine enough

A coarse grid under-resolves gradients and small targets, so DVH statistics and hotspot values become unreliable. `max_spacing_mm` applies to in-plane and slice spacing.

- **Default severity:** warning
- **Requires:** RTDOSE
- **Applies to:** every plan
- **Reference:** RT Dose Module - PixelSpacing, GridFrameOffsetVector
- **Parameters (defaults):**
  - `max_spacing_mm`: `3.0`

### DOSE-004 - Maximum dose does not exceed the hotspot limit

Maximum dose anywhere in the grid, as a percentage of the highest prescription (normalised to the 100% level when the plan is prescribed to an isodose line, e.g. Gamma Knife). A value far above the limit usually means a wrong prescription, wrong dose file or a normalisation error.

- **Default severity:** warning
- **Requires:** RTPLAN, RTDOSE
- **Applies to:** electron, ion, neutron, photon, proton
- **Reference:** Local policy (typical 107-115% of prescription)
- **Parameters (defaults):**
  - `max_percent_of_rx`: `110.0`
  - `prescription_isodose_percent`: `0.0`
  - `use_vendor_isodose`: `true`

### DOSE-005 - Target volumes lie inside the dose grid

If a target extends beyond the calculated grid, dose statistics for it are computed on part of the volume only - or none of it if the grid is shifted (wrong origin, wrong patient position).

- **Default severity:** error
- **Requires:** RTSTRUCT, RTDOSE
- **Applies to:** every plan
- **Reference:** RT Dose Module - ImagePositionPatient; Structure Set contours
- **Parameters (defaults):**
  - `target_patterns`: `["^PTV"]`

### DOSE-006 - Target coverage (DVH point) meets the prescription

Samples the dose grid at voxel centres inside each declared target and checks that Dx% (default D95) reaches a fraction of that target's own prescription. This ties plan, structure set and dose together; it is a screen, not a substitute for the planning system's DVH.

- **Default severity:** warning
- **Requires:** RTPLAN, RTSTRUCT, RTDOSE
- **Applies to:** electron, ion, neutron, photon, proton
- **Reference:** Local policy (typical: D95 >= 95% of prescription)
- **Parameters (defaults):**
  - `volume_percent`: `95.0`
  - `min_percent_of_rx`: `95.0`
  - `target_patterns`: `[]`

## Protocol compliance (ruleset-driven)

### DVH-001 - Protocol dose-volume constraints are met

Evaluates each constraint of the ruleset's `constraints` list against the dose grid: ROI name regexes select (and union) the structures, optional `exclude` regexes are subtracted (e.g. brain minus target), `metric` is Dmax, Dmean, D95%, D2cc, V12Gy, V95%..., compared with `op` and `limit` in `unit`. Every constraint must carry a `source` citation. A constraint whose ROI is absent fails (an unverifiable constraint is not a passed one) unless it is marked `optional: true`, in which case the check is recorded as not contoured. Voxel-centre sampling: a consistency screen, not the planning system's DVH.

- **Default severity:** error
- **Requires:** RTSTRUCT, RTDOSE
- **Applies to:** every plan
- **Reference:** Ruleset-supplied (see each constraint's `source`), e.g. HyTEC, QUANTEC, protocol documents
- **Parameters (defaults):**
  - `constraints`: `[]`
